# Raw pet drops and floor admission

Raw pet eggs from regular, bonus, map and MVP monster rewards now enter the same durable Asset entitlement path as other pet rewards. A floor source retains normal owner priority. Admission reserves that source using the complete immutable transaction identity; it does not remove the floor or send acquisition success. Busy/unavailable admission leaves the source collectible. Party distribution retains the existing random/round-robin selection and tries eligible recipients through the admission callback. Direct MVP rewards remain assigned to the MVP recipient.

Committed acknowledgement removes the reserved source once and emits pickup/MVP/party acquisition feedback. Rejection unlocks it. A pending floor cannot expire or be copied into monster/pet loot storage. Administrative cleanup may remove the ephemeral floor, but it does not cancel an indeterminate payment/reward result. The detached immutable request remains available for retry and receipt resolution after its original player disconnects; matching terminal acknowledgement releases the map shop fence even without that player object. Floor ID reuse cannot remove a different object. New-character sessions cannot receive the original character's pickup feedback.

The map's monster and floor state is ephemeral and is not replayed after process restart. Therefore a committed reward survives through its SQL entitlement and receipt while the old floor disappears; retry never creates a second entitlement. Before commit, no acquisition success has been announced. A crash that loses an uncommitted ephemeral drop retains the existing world-drop durability boundary. This change does not introduce a persistent monster death log or promise recovery of every unacknowledged floor item.

Encoded player-dropped pet eggs retain the existing transfer path. They are not converted into new pet identities. A separate preexisting source-persistence race remains: player A exposes an encoded egg on the floor before A's inventory deletion is saved; B picks it up and is saved; a map crash can then reload A's old saved egg as well. Solving that trace requires durable drop-source removal/transfer, not a raw reward entitlement. The raw floor work does not claim atomicity for that separate transfer channel.

`pet_floor_test.py` runs the exact reservation, party selection and floor-expiry bodies under ASan/UBSan with explicit world/SQL-admission doubles. The shop inter test executes exact detached retry/acknowledgement handlers. Real SQL proof runs the production Asset transaction for multi-egg rollback, departed-owner rejection, committed detached replay, character mismatch and MariaDB restart. SQL fields `pet_floor_asset` and `pet_floor_restart` are required in the pets release evidence. Test definition is not execution evidence; the candidate must run the SQL suite before release.
